# Phase 4b: AI 画面（チャット・引用ジャンプ・矩形選択の AI 解説）

> 状態: **実装済み（2026-11-08、#36〜#38）**。承認は 2026-11-07。実装は 3 PR に分ける: (1) AI タブ・ストリーミング・引用ジャンプ・会話（R1〜R3、R6〜R8）、(2) 横断の AI 画面（R4）、(3) 矩形選択の AI 解説（R5）。バックエンドは Phase 3d（`specs/phase3d.md`、#27〜#34）で main にある。

## 目的
3d で作った API（`POST /chat`、`POST /papers/{id}/explain-region`、会話の一覧・取得・削除、`GET /chat/status`）を、Web 画面から使えるようにする。読んでいる論文について質問し、回答の根拠をクリックすると、PDF の該当箇所が開いてハイライトされる。図・数式・表を矩形で選んで、その場で解説を読める。

## 要件
- [x] R1: 論文画面の右ペインに「AI」タブを足す（ノート・書誌・注釈の隣）。質問を送ると回答が 1 文字ずつ流れて表示され、「停止」で途中で止められる（止めた回答も「中断」と表示して残る）。
- [x] R2: 回答の `[1]` などの引用は、サーバーが返した `label`（例 `p.4, Sec 3.2`）のバッジで表示する。同じ論文の引用をクリックすると、PDF がそのページへスクロールし、引用の範囲（`bboxes`）を一時的にハイライトする。
- [x] R3: AI タブには、その論文の自分の会話の一覧を出す。会話を開いて続きを質問でき、削除できる。新しい会話も始められる。
- [x] R4: 画面上部に「AI」の入口を足し、ライブラリ全体に質問する画面を出す。範囲は「すべてのワークスペース」か、ワークスペース 1 つを選べる。引用は論文名つきのバッジで、クリックすると、その論文の画面がそのページ・位置で開いてハイライトされる。横断の会話の一覧・続き・削除もこの画面で行う。
- [x] R5: PDF の矩形選択に「AI で解説」を足す。選んだ範囲を画像（PNG、長辺 2048 px 以下）に切り抜いて、矩形の座標（PDF のポイント、原点左下）と一緒に送る。任意の質問を添えられ、回答は AI タブに流れる。注釈の編集権限がない閲覧者でも使える（注釈は作らない）。
- [x] R6: AI が使えないときは、使えない理由を表示し、入力欄を無効にする。理由ごとの表示は次のとおり。
  - チャットが無効（`enabled: false`）: admin には有効化の手順（README の節へのリンク）、それ以外の人には「管理者が有効にすると使える」と出す。
  - 画像に対応していない（`vision_available: false`）: 「AI で解説」を出さない。
  - 1 日の上限（429 `daily_limit`）、混雑（429）、AI の応答なし（502、または回答中の `error`）: それぞれ専用の文言を出す。
  - 検索が劣化した（`degraded: true`）: 「キーワード検索だけで答えた」と小さく出す。
- [x] R7: 回答の Markdown は、画像と生の HTML を出さずに表示する（`![..](..)` は描画せず、`<img>` も作らない）。リンクは `rel="noopener noreferrer"` で新しいタブに開く。
- [x] R8: 文言はすべて `ja` / `en` の辞書に入れる（`npm run typecheck` が未翻訳を拒否する）。

## スコープ外
- 回答の再生成、途中の質問の編集、会話のタイトルの変更、会話の共有・エクスポート
- 回答を注釈やノートに保存するボタン（コピーで足りる）
- 引用の範囲を PDF に恒久的なハイライトとして残すこと（表示は一時的）
- 複数の論文を選んで比較する画面（横断チャットで質問すれば足りる）
- AI の設定画面（`.env` で設定する。画面からキーを入れさせない）
- Claude での実機確認（R13）。費用がかかるため行わず、Ollama での確認をもって完了とする（ユーザー判断 2026-11-07）
- モバイル向けの専用レイアウト（既存の縦並びのまま使えればよい）

## 受け入れ基準
開発環境の API を Ollama（`qwen2.5vl:7b`）に向けて起動し、ブラウザ（Playwright）で次を確かめる。
1. 論文画面の AI タブで質問すると、回答が流れて表示され、引用のバッジが出る。バッジをクリックすると、PDF がそのページに移り、ハイライトが出る。
2. 回答の途中で「停止」を押すと止まり、会話を開き直すと「中断」の回答が残っている。
3. AI タブの一覧に会話が出て、開くと続きを質問でき、削除すると一覧から消える。
4. 「AI」画面でライブラリ全体に質問すると、引用に論文名が付く。別の論文のバッジをクリックすると、その論文がそのページで開く。
5. 矩形を選んで「AI で解説」を押すと、解説が AI タブに流れる。閲覧者（`qa-viewer`）でも使える。
6. `LLM_PROVIDER=none` で起動し直すと、AI タブと AI 画面に「無効」の案内が出て送信できない。admin にだけ README へのリンクが出る。
7. 回答に `![x](http://example.com/a.png)` を含めても画像は読み込まれない（Network に example.com への要求が出ない）。fake の LLM は本番に入れないので、これは表示部品に固定の文字列を渡して確かめる。
8. `npm run lint`・`npm run typecheck`・`npm run build` が通る。CI が green。

## 決めたこと
- **SSE は `fetch` のストリームで読む**: `EventSource` は POST できないため。停止は `AbortController` で切断し、サーバー側がそれを検知して `cancelled` で保存する（3d で実装済み）。新しい依存は足さない。
- **正しい本文は `done` のほう**: 流れている間は `delta` を足して見せ、`done` が来たら、その `content` と `citations` に置き換える（サーバーが検証した本文が正、という 3d の決定どおり）。
- **座標の変換はフロントで行う**: 引用の `bboxes` は PDF のポイントで原点が左下、ビューアは原点が左上なので、ページの高さで y を反転してからハイライトする。矩形選択はその逆に変換して送る。
- **切り抜きは表示中のページの canvas から**: PDF.js が描画した canvas の該当範囲を `toBlob` で PNG にする。長辺が 2048 px を超えるときは縮小する。サーバー側でも検証・再エンコードする（3d）。
- **閲覧者も AI で解説できる**: 解説は論文のデータを書き換えず、会話は本人だけのものなので、注釈の権限とは分ける。今の矩形選択は注釈の作成と同じく `canEdit` のときだけ有効なので、閲覧者には「AI で解説」専用の矩形選択を出す。
- **別の論文の引用への移動**: 論文画面の URL にページと位置を載せ（例 `/papers/<id>?page=4&hl=<chunk_id>`）、開いたときにそこへ移ってハイライトする。チャンクの位置は、すでにある chunks API（`GET /papers/{id}/chunks?page_from=4`）で、そのページのチャンクを取って ID で探す。
- **AI の入口は上部のナビ**: ライブラリ・追加・設定の並びに「AI」を足す。
- **Markdown は既存のノートと同じ部品**（`react-markdown` + `rehype-sanitize`）を使い、`img` を描画しない設定を足す。
- **自動テストは足さない**: フロントにはテストの仕組みがない（CI は lint・typecheck・build）。受け入れ基準はブラウザで確かめる。

## 確認の結果（2026-11-08）
- 開発環境の API を Ollama（`qwen2.5vl:7b`）に向けて、ブラウザで受け入れ基準 1〜7 を確かめた。`qwen2.5vl:7b` は `[n]` をほとんど書かないので、引用のバッジとジャンプ（1・4）は、引用つきの回答を開発用 DB に入れて確かめた（確認後に削除）。
- 6 の admin 向けの表示（README へのリンク）は、admin のテストユーザーがいないため、コードで確かめた。閲覧者向けの表示はブラウザで確かめた。
- 5 は owner（図）と `qa-viewer`（数式）で確かめ、どちらも注釈は作られなかった。
- 既存の問題（4b より前から）: 論文画面の `canEdit` は、論文のワークスペースではなく、右上で選んでいるワークスペースの権限で決まる。閲覧者が「Personal」を選んだまま共有の論文を開くと注釈の道具が出る（保存は API が拒否する）。
